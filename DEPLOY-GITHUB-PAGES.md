# Сайт на GitHub Pages

## Как сайт опубликован сейчас

- **Адрес сайта:** https://harutyun-mkhitaryan.github.io/mariam-birthday/
- **Репозиторий:** https://github.com/Harutyun-Mkhitaryan/mariam-birthday (публичный)
- Ветка **`main`** — исходники проекта (эта папка).
- Ветка **`gh-pages`** — уже собранный сайт. GitHub Pages показывает именно её
  (**Settings → Pages → Source: Deploy from a branch → gh-pages → / (root)**).

Сайт собран один раз и выложен готовым, поэтому **сам он не обновляется**: если изменить файлы в `main`,
на сайте ничего не поменяется, пока не обновить ветку `gh-pages`.

### Как обновить сайт после изменений

Нужен установленный Node.js. В папке проекта в PowerShell:

```powershell
npm install
$env:SITE_URL='https://harutyun-mkhitaryan.github.io'; $env:BASE_PATH='/mariam-birthday'
npm run build
```

Затем содержимое папки `dist` нужно отправить в ветку `gh-pages` (заменив старое содержимое).
Проще всего попросить об этом Claude: он пересоберёт и отправит сам.

Чтобы сайт обновлялся автоматически после каждого изменения, перейдите на сборку через GitHub Actions —
она описана ниже. Для неё у входа GitHub CLI должно быть право `workflow`
(`gh auth refresh -s workflow`), а в **Settings → Pages → Source** нужно выбрать **GitHub Actions**.

> Репозиторий публичный: файлы сайта (картинки, видео, текст письма) может открыть любой, у кого есть ссылка.
> Поисковикам страница запрещает себя индексировать, но секретной она не является.

# Автоматическая сборка через GitHub Actions (необязательно)

Ниже — способ, при котором GitHub сам собирает и публикует сайт после каждой отправки изменений.

## Шаг 1. Положите файл сборки на место

GitHub ищет инструкцию по сборке только в папке `.github\workflows`. Создать её за вас я не мог
(это защищённая системная папка), поэтому сделайте это вручную, это одна минута:

1. Откройте папку `mariam-birthday-site` в Проводнике.
2. Создайте в ней папку с именем `.github` (с точкой в начале).
3. Внутри `.github` создайте папку `workflows`.
4. Перенесите файл `deploy.yml` из `mariam-birthday-site` в `.github\workflows`.

Должно получиться: `mariam-birthday-site\.github\workflows\deploy.yml`.

## Шаг 2. Создайте репозиторий из папки проекта

*(Уже сделано: репозиторий `mariam-birthday` создан. Этот и следующий шаг нужны только для нового проекта.)*

1. Откройте GitHub Desktop и войдите в свой аккаунт GitHub.
2. Меню **File → Add local repository…** и выберите папку `mariam-birthday-site`
   (именно её, а не папку уровнем выше).
3. Программа скажет, что в папке ещё нет репозитория, и предложит его создать — нажмите
   ссылку **create a repository**.
4. В окне оставьте всё как есть:
   - **Name** — имя репозитория, оно станет частью адреса сайта. Например `mariam-birthday`
     даст адрес `https://ВАШ_ЛОГИН.github.io/mariam-birthday/`. Используйте латиницу без пробелов.
   - **Git ignore** — `None` (нужный файл `.gitignore` уже лежит в проекте).
   - README и License не добавляйте.
5. Нажмите **Create repository**.

## Шаг 3. Отправьте проект на GitHub

1. Нажмите **Publish repository** (синяя кнопка вверху).
2. **Снимите галочку «Keep this code private»** — иначе GitHub Pages на бесплатном аккаунте не включится.
3. Нажмите **Publish Repository** и дождитесь окончания загрузки (около 60 МБ).

## Шаг 4. Включите GitHub Pages

1. Откройте репозиторий на github.com (в GitHub Desktop: **Repository → View on GitHub**).
2. **Settings → Pages** (в левом меню, раздел «Code and automation»).
3. В блоке **Build and deployment** в списке **Source** выберите **GitHub Actions**.
   Больше ничего выбирать и сохранять не нужно.

## Шаг 5. Запустите сборку

Первая сборка стартовала сразу после загрузки, ещё до включения Pages, поэтому она,
скорее всего, завершилась ошибкой. Это нормально, просто запустите её ещё раз:

1. Вкладка **Actions** → слева **Deploy to GitHub Pages**.
2. Справа кнопка **Run workflow → Run workflow**.
3. Через 3–5 минут у запуска появится зелёная галочка.

## Шаг 6. Откройте сайт

Адрес показан в **Settings → Pages** («Your site is live at…») и выглядит так:

```
https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/
```

Эту ссылку и отправляйте Мариам. Откройте её сами на телефоне и на компьютере и проверьте
видео, письмо и галерею.

## Как потом что-то изменить

1. Измените файлы в папке проекта (например, текст в `src/data/site.ts` или видео в `public/video/`).
2. В GitHub Desktop слева появится список изменений. Внизу впишите короткое описание в поле
   **Summary** и нажмите **Commit to main**.
3. Нажмите **Push origin**. Сайт пересоберётся и обновится сам за несколько минут.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| Красный крестик в Actions, ошибка на шаге **deploy** про Pages | Pages ещё не включён: выполните шаг 4, затем шаг 5. |
| В Settings → Pages нет варианта для публикации | Репозиторий приватный. **Settings → General → Danger Zone → Change visibility → Public**. |
| Сайт открылся без оформления и картинок | Сайт собран не через Actions. Проверьте, что в **Source** стоит **GitHub Actions**, а не «Deploy from a branch». |
| По адресу ошибка 404 | Подождите 1–2 минуты после зелёной галочки и обновите страницу. Проверьте адрес: имя репозитория в нём пишется точно так же, как на GitHub. |
| На вкладке Actions нет «Deploy to GitHub Pages» | Файл `deploy.yml` лежит не там. Проверьте путь из шага 1: `.github\workflows\deploy.yml` (папка `workflows` — во множественном числе). После исправления сделайте Commit и Push. |

## Что важно не трогать

- Папку `.github` — в ней инструкция для GitHub, как собирать сайт.
- Файл `package-lock.json` — он фиксирует версии, с которыми сайт проверен.
- Папки `node_modules` и `dist` на GitHub не отправляются (они перечислены в `.gitignore`), так и должно быть.

## Свой домен (необязательно)

Если подключите собственный домен в **Settings → Pages → Custom domain**, откройте
`.github\workflows\deploy.yml`, раскомментируйте блок `env` и укажите адрес:

```yaml
        env:
          SITE_URL: https://ваш-домен.example
          BASE_PATH: /
```

## Запасной вариант без сборки на GitHub

Папка `dist` — это уже готовый сайт с относительными ссылками, он работает из любой папки на любом
хостинге. Его можно выложить и без Actions: загрузите **содержимое** `dist` в отдельный репозиторий
и в **Settings → Pages → Source** выберите **Deploy from a branch → main → / (root)**.
Основной способ выше удобнее: сайт обновляется сам после каждого изменения.
